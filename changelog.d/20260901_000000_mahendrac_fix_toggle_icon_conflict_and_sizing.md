- [BugFix] Header user-menu toggle's fallback account icon (`DesktopUserMenuToggleAvatar` in `CustomHeaderUserMenuDropdown.jsx`) wasn't visibly showing on `account`/`gradebook`/`learner-dashboard`/etc. Root cause, found via live DOM inspection: the fallback icon `<span>` reused Bootstrap's generic `avatar` class, which an existing `_header.scss` rule (`#root header .menu-trigger .avatar`, written for the *native* toggle's icon) also matched — forcing it to 1.25rem/transparent via `!important`, regardless of this component's own styling. Fixed by dropping the `avatar` class from that span, then reworking `.tels-user-menu-toggle-avatar-container` in `tels-brand-openedx/paragon/_header.scss` to reuse that same native icon's own `tels-header-user-icon-box` mixin and 1.25rem sizing (matching every other header icon) instead of inventing a separate size, with the same explicit-size-all-the-way-down `!important` treatment extended through the extra `.pgn__icon` wrapper span Paragon's `<Icon>` component adds (the native rule styles a raw inline SVG directly, no such wrapper) — needed because Paragon's own `core.css` (`.pgn__icon svg { width: 100%; height: 100%; }`) doesn't reliably resolve through this markup's nested `inline-flex` ancestor chain (confirmed live in DevTools: the icon rendered outside its circle instead of filling it).
